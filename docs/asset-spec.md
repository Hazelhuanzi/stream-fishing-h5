## 1. 技术总则（硬要求）

1. **透明背景**：PNG-24 带 alpha 通道。不要白底、不要灰色棋盘格、不要“假装透明”的浅色底。
   - 现在代码里用 `mix-blend-mode` 把白底“融”进画面，这只对白底图有效。换成真正的透明图后这些 hack 会全部删掉。
2. **不要烘焙阴影 / 地面投影 / 光晕**。需要阴影由代码加，否则锚点一变就露馅。
3. **不要文字、水印、签名、边框、画框、拼图式多格排版**。一张图只放一个主体。
   - ⚠️ 现有 `stream-bg.png` 右下角有「豆包 AI 生成」水印；代码里暂时放大了背景把它裁掉。**正稿必须干净。**
4. **导出尺寸 = 游戏内显示尺寸 × 2**（Retina），源文件可以更大，最终由打包脚本压到 WebP。
5. **同组素材必须同画布、同锚点、同比例**：
   - 第一人称猫爪的 4 个状态必须能叠在一起严丝合缝，否则换姿势时会“跳”。
   - 第一人称鱼竿单独一张；握把锚点必须和猫爪的锚点一致。
   - 常客猫的每个状态组同理（v2 再做）。
   - 4 条鱼必须同画布同朝向，否则图鉴格子里大小不一。
6. **四边留 2% 透明边**，主体不要贴边，避免缩放时被裁。
7. 朝向：4 条鱼统一**朝左**（与现有豆包素材一致；四条必须一致，代码可整体镜像）。猫爪沿鱼竿方向朝左上；常客猫各朝向固定，同组内一致。

## 2. 素材清单

### 2.1 背景

| 字段 | 要求 |
|---|---|
| 文件名 | `stream-bg.png` |
| 画布 | 1440 × 2560（9:16） |
| 透明 | 否（不透明，允许 JPG/WebP 源） |
| 内容 | 只画环境：天空、溪流、石头、草丛。**不要画猫、鱼、浮漂、鱼竿、UI。** |

**构图安全带**（代码里元素固定在下列位置，背景要在这些区域“留白/简单”）：

| 区域 | 屏幕位置（宽 × 高） | 要求 |
|---|---|---|
| 顶部 HUD | 0–18% 高，整宽 | 浅色、低对比，上面会压半透明白卡片 |
| 浮漂水域 | 中心约 (47.5%, 44.6%)，占宽 27% | 必须是开阔水面，有波纹空间 |
| 第一人称握竿区 | 右下，x 68%–100%，y 76%–100% | 简单岸边/水面；猫爪和竿会盖住 |
| 左下按钮 | x 4%–58%，y 88%–100% | 简单背景 |
| 鱼线经过 | 从约 (60%, 32%) 到 (47%, 45%) | 不要有高对比线条 |

> 背景只画环境，**不要画浮漂、鱼线、鱼竿、猫爪、猫脸、UI**。

> 如果最终背景的构图和上面差异很大，不用重画——我们改配置表里的锚点坐标即可，但最好在第一版就对齐，省一次返工。

### 2.2 猫

#### 2.2.1 第一人称猫爪（v1 要产）

| 文件名 | 触发时机 | 建议内容 |
|---|---|---|
| `paws-idle.png` | 待机 / 等待咬钩 | 两只爪子松松握着竿 |
| `paws-grip.png` | 咬钩 | 抓紧，指节收紧 |
| `paws-reel.png` | 收线 | 用力往回拉 |
| `paws-cast.png` | 抛竿瞬间 | 一只爪子前送 / 甩出 |

统一规格：

| 字段 | 要求 |
|---|---|
| 画布 | 1200 × 700（12:7） |
| 透明 | 是 |
| 锚点 | **竿握把中心 = 画布 (70%, 85%)**；4 张图同一锚点 |
| 构图 | 两只猫爪从画布底边伸入，握住一根斜向左上的竿（竿另画）；爪子在画布下部约 60% |
| 比例 | 同一只猫、同一大小；爪子合计占画布宽约 55–65% |
| 风格 | 扁平/简笔、粗描边（方案 A），与背景水彩色调统一 |
| 游戏内显示 | 宽约屏幕 40%，放在右下；竿握把与它对齐 |
| 备注 | 现在代码里是 CSS 占位；正稿按这个锚点画，代码只改配置 |

> 第一人称不需要猫脸 / 身体。情绪靠爪子松紧、鱼竿动作、浮漂水花、震动和文案。

#### 2.2.2 玩家猫全身立绘（非钓鱼界面，v1 可选）

- 用在标题、图鉴、猫友等界面；v1 可先复用现有 `cat-sheet.png`。
- 若要新画：1000 × 1200，透明，底边中心锚点，5 个状态（idle / nervous / reel / sad / happy），同画布同比例。
- **不进入钓鱼场景。**

#### 2.2.3 常客猫（v2 再产，第一版不画）

猫咪后院式的来访猫。第一版不做，先留命名和约束，避免以后返工。

| 字段 | 要求 |
|---|---|
| 文件名 | `visitor-<id>-<state>.png`，如 `visitor-orange-idle.png`、`visitor-orange-eat.png` |
| 状态 | `idle`（待着）、`eat`（吃鱼 / 小食）、`gift`（回礼）、`leave`（离开）；第一版只预留 |
| 画布 | 1000 × 1000（1:1） |
| 透明 | 是 |
| 锚点 | 底部中心 (50%, 100%) |
| 比例 | 同一只猫的所有状态同画布、同大小；不同猫之间体型可不同，但同一只必须稳定 |
| 风格 | 与猫爪同一套粗描边 / 平涂；用颜色和花纹区分性格，不加文字 |
| 游戏内显示 | 宽约屏幕 18–25%，在岸边 / 石头上出现 |

> 常客猫不要画成“宠物立绘”，要像“刚好坐在那里的猫”：姿态低、占地小，不抢玩家猫的视觉重心。

### 2.3 鱼（4 种）

| 文件名 | 鱼种 |
|---|---|
| `fish-pangpi.png` | 鳑鲏 |
| `fish-baitiao.png` | 白条 |
| `fish-yingu.png` | 银鲴 |
| `fish-heiqiquan.png` | 黑鳍鳈 |

统一规格：

| 字段 | 要求 |
|---|---|
| 画布 | 768 × 768（1:1） |
| 透明 | 是 |
| 朝向 | 统一朝左（与现有素材一致），完整侧视，不要裁剪鱼鳍 |
| 构图 | 鱼身水平居中，占画布宽约 85%；**主体必须落在画布纵向 12.5%–87.5% 之间**（卡片是 4:3 裁切，超出会被切） |
| 游戏内显示 | 卡片里约 280 px 宽；收集格子里是圆形放大裁切，所以鱼头要靠近画面中心 |
| 风格 | **保留水彩插画质感**（方案 A 的例外：鱼是收藏主体，卡片里要看细节），不要做成扁平图标 |
| 一致性 | 4 条鱼用同一镜头距离、同一笔触精细度 |

## 3. 给图像 AI 的提示词模板

一次只生成一张，先生成 3 个候选挑 1 个，不要让它一次出九宫格。

```
只生成一张游戏素材：【素材名】。
内容：【一句话描述，例如“两只小猫爪子握着一根斜向左上的竹竿，第一人称画面底部视角，不画猫脸”】。
风格：【§0 的关键词 + 参考图风格】。
构图：【画布尺寸】；主体【朝向 / 位置 / 锚点】；四周留约 2% 空白。
技术要求：纯透明背景（alpha 通道），不要白底，不要文字、水印、签名、边框，
不要画阴影落地投影，主体完整不裁切，不要九宫格，不要拼图。
输出：单张 PNG，【画布尺寸】。
```

> 图像 AI 经常“透明背景”失败。出来后先在深色背景上检查一圈：边缘有没有白边、背景是不是真的透明。不合格就重生成，不要拿来凑合。

## 4. 替换流程（我来维护）

1. 新素材放进 `assets/fishing/`，文件名严格按上表。
2. 运行素材构建脚本（待我补）：裁透明边 → 缩放到 2× 显示尺寸 → 转 WebP → 更新 `assets/manifest.js`。
3. 如果新素材的锚点和上表不同，只改 `manifest.js` 里的锚点/显示尺寸，**不碰玩法代码**。
4. 打开游戏逐项检查：猫的表情切换会不会跳、鱼在卡片里有没有被裁、背景上的浮漂区是否还合理。

## 5. 占位机制（开发期用，不进最终版）

代码会支持 `?placeholder` 开关：

- 缺图或开关打开时，用**纯色块 + 文件名**按真实显示尺寸占位。
- 目的：玩法和手感不依赖素材进度；素材到位后逐个替换，一眼能看出哪个还没换。
- 占位图永远不会打包进上线版本。
