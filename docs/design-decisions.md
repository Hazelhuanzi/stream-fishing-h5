## D1 · 玩家身份与「猫友」关系 ✅ 已定（2026-11-28）

| 项目 | 决定 |
|---|---|
| 玩家角色 | **奶牛猫**（IP 本体），溪边钓点的小主人 |
| 其他猫 | **猫友 / 常客 / 客人**，不是宠物 |
| 关系性质 | 招待、分享、交朋友；**不是驯养** |
| 猫友出现方式 | 钓鱼过程中在旁边发生，不做独立的养成管理界面 |
| 起名 | 亲近度达到阈值后，猫友「记住你」，玩家可以给它起名 |

### 三种渔获处置

| 处置 | 获得 | 叙事含义 |
|---|---|---|
| 放流 | 金币 + 图鉴 | 对鱼：不占有 |
| 带回家 | 鱼缸 | 对鱼：养育 |
| 分享给猫友 | 亲近度 | 对猫：交朋友 |

> **为什么这样定**：避免「猫训猫」的违和；保留奶牛猫 IP；同时贴合概念文档「钓到又放回、不追求渔获」的内核。

### 文案替换表（全项目统一）

| 不再使用 | 改为 |
|---|---|
| 驯化 / 驯服 | 混熟 |
| 投喂 | 分享渔获 / 请客 |
| 野猫串门 | 猫友来访 |
| 认识你 | 记住你 / 成为常客 |
| 羁绊值 | 亲近度（系统可叫「猫友」） |
| 猫粮猫条 | 猫友小食（可选） |

## D2 · 经济与商店 ✅ 已定原则（2026-11-28）

| 资源 | 获得方式 | 用途 |
|---|---|---|
| 鱼力值 | 钓上鱼即得 | 解锁新场景 |
| 金币 | 放流获得 | 钓具升级、角色配饰、可选猫友小食 |
| 亲近度 | **分享渔获**为主 | 猫友成为常客、起名、回礼 |

- 商店分两个 tab：**「钓具与装扮」** / **「猫友小食」**。
- 猫友小食是**可选加速**，不是涨亲近度的唯一途径；不买也能靠分享渔获混熟。
- 第一版（v1）不实现经济与商店，只预留数据接口。

> **为什么**：金币买小食本身不怪，怪的是「买猫粮驯服小猫」。改成「招待猫友」后，花钱和交朋友都说得通。

## D3 · 视觉风格 ✅ 已定 A（2026-11-28）

**方案 A：水彩场景 + 扁平/简笔角色 + 猫咪后院式的留白与少按钮。**

| 层 | 处理 |
|---|---|
| 场景 / 背景 | 国风水彩绘本，柔和漫射光，尽量还原现有溪流参考的质感 |
| 玩家猫 / 常客猫 | 扁平或简笔、粗描边、表情夸张，便于做多状态 |
| 鱼 | **建议**保留水彩插画质感（收藏卡需要细节），不做扁平图标 —— 待确认 |
| UI | 扁平、低饱和、大留白、少按钮，学《猫咪后院》的呼吸感 |

**不采用：**
- 全盘照搬《猫咪后院》的扁平矢量画面 —— 会丢掉水彩 IP 和课题的「画面氛围」强项。
- 全水彩角色 —— 猫的多表情/多状态成本高，AI 很难稳定保持同一只猫。

> **为什么**：混合风是辨识度与生产成本的最佳平衡；而且你自己的参考图（水彩溪流 + 简笔猫）已经指向这个方向。

## D4 · 换装范围 💡 建议（待确认）

- 第一版只做**配饰**：帽子、围巾、鱼篓、鱼竿皮肤。
- **不做**换猫本体皮肤（橘猫/三花/狸花）。
- 理由：奶牛猫是 IP 和故事主角；多猫同屏时换本体会混淆「哪只是我」。

## D5 · 第一版范围 💡 建议（待确认）

**竖切：一条最小但完整的体验。**

| 做 | 不做（留到后续） |
|---|---|
| 1 个场景（溪流） | 多场景、昼夜 |
| 4–6 种鱼 | 亚种、异色、尺寸个体 |
| 抛竿 → 等口 → 抬竿 → 收线 → 上鱼 | 猫友、鱼缸、商店、转盘 |
| 图鉴、放流记录 | 金币/鱼力值经济 |
| 音效、震动、手机适配 | 换装、皮肤 |

> 数据层可以预留字段，但界面和玩法先不做。

## D6 · 钓鱼主视角 ✅ 已定（2026-11-28）

**严格第一人称。** 画面底部是两只猫爪 + 向外伸出的竹竿 + 鱼线 + 浮漂，看不到猫脸。

| 项目 | 决定 |
|---|---|
| 主视角 | 第一人称，低机位俯视水面 |
| 画面元素 | 猫爪在底部偏右；竹竿从右下伸向左上；鱼线从竿尖垂到水面浮漂 |
| 玩家猫全身立绘 | 不进入钓鱼场景；保留给标题、图鉴、猫友等非钓鱼界面 |
| 情绪反馈 | 爪子姿态 + 鱼竿动作 + 浮漂/水花 + 震动 + 文案，不靠猫脸 |
| 浮漂位置 | 画面左中水面（约 47.5%, 44.6%），与竿尖拉开距离 |

> **为什么**：保留「我就是这只小猫」的代入感；猫脸虽然可爱，但第一人称能让钓鱼动作更直接。全身立绘以后用在非钓鱼界面补足 IP。

## D7 · 第一版平台 ✅ 已定（2026-11-28）

**先用 H5 网页原型。**

- 基于现有 `index.html` 迭代，手机浏览器 / 微信内打开即可玩。
- 玩法、数值、素材规格定稿后，再决定是否移植微信小游戏。
- 移植时界面层（DOM/CSS）要重写，但状态机、鱼类数据、存档逻辑可以复用。
- 小程序套网页需要企业主体资质，不作为第一版方案。

> **为什么**：玩法还在改，先用最短路径验证手感；小游戏重写成本高，不适合在机制未定时做。

## D8 · 陀螺仪 ✅ 已定：第一版做测试关（2026-11-28）

| 项目 | 决定 |
|---|---|
| 抛竿 | 快速前甩手机（beta 角减小）触发 |
| 抬竿 | 咬钩窗口内快速上挑手机（beta 角增大）触发 |
| 收线 | 第一版保留点按，不强制体感 |
| 辅助 | 灵敏度滑杆、校准当前姿势、反转方向 |
| 兼容 | 保留点按/空格作为 fallback；电脑可用「模拟抛竿 / 模拟咬钩 / 模拟抬竿」 |
| 平台限制 | iOS 需要 HTTPS + 用户手势授权；开启入口放在「体感」设置里 |

> **为什么**：陀螺仪是手感风险最高的部分，必须最早验证；如果不好玩，现在改设计还来得及。

## 对素材规格的影响

- **钓鱼场景**：v1 要产「第一人称猫爪 4 状态」+「第一人称鱼竿」；不产全身猫立绘。
- **非钓鱼界面**：玩家猫全身立绘以后用于标题/图鉴/猫友；v1 可先复用现有 `cat-sheet.png`。
- **常客猫**：v2 再产，命名规范先留好 `visitor-<id>-<state>.png`。
- **浮漂**：位置改到画面左中（约 47.5%, 44.6%），背景那片水要留空。
- 所有素材的锚点、画布、透明要求见 `docs/asset-spec.md`。
